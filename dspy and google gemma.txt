google/gemma-3-270m
- no nano model (only E2B and E4B are nano models)
- size: 400mb (16 bit default), 292mb (8 bit on ollama), 32k context window
- instruction tuning version also present on huggingface (supervised fine tuning) used
- good: vocabulary, story telling, summarization, data extraction, text translation
- pathetic: knowledge, maths
- needs low temperature like 0
- runs faster
- low latency for no knowledge tasks
- good for pocket friendly devices
- sensitive to quantization
- model is a building block. needs to be fine tuned on our dataset for knowledge (full fine tuning method. use FP32)
- only text input for 270m, 1b models. above them, text and image
- 270m, 1b, 4b, 12b, 27b available on ollama
- ios: swift-transformers via swift, coremltools package: .mlpackage
- android: llm mlc


dspy
- inbuilt pipelines for qna, text summarization, classification, multimodal image classification
- supports openai, gemini, anthropic, databricks, ollama, together, azure, sglang (gpu)
- signatures for the inbuilt pipelines to instruct llm what to do
- metrics for faithfulness to analyze how true is the information
- can create custom signatures based on our inputs and outpus
- modules such as predict (fundamental), chain of thought (improves quality), program of thought (generates code for each inference)
- settings.configure module for observability, also integrable with langfuse
- dspy.inspect_history for understanding the background process for each inference. based on the system prompt, it finds out the objective of the program
- uses signatures as system prompt, then inputs and with own reasoning generates the output
- i didn't understand adapters
- optimizers for fine tuning. bsfewshot (1-10 examples), bsfewshotwithrandomsearch(10-50), miprov2(0 or upto 200), bsfinetune (> 7B param models)


dspy optimizers
bootstrapfewshot:
- bootstrapping: using model's own predictions as training examples to improve itself
- runs on a metric to perform bootstrapping (in our case accuracy metric based on cosine similarity)
- uses a teacher model (can be gpt 4o) to generate full execution traces (reasoning using chain of thought and output) on training data and select the best examples as demos for predictions
- if no teacher model is specified, it uses the student model (gemini flash lite/gpt-oss)
- performs bootstrapping where the model's response is compared to the gold answer.
- max_bootstrapped_demos = 16, 16 examples with the best cosine similarity score
- max_labeled_demos = 4, 4 synthetic examples generated by the model
- metric_threshold = 0.8, the cosine similarity's score should be > 0.8 to select the 16 examples

dspy modules
program of thought:
- need to install deno on Linux/mac for execution
- generates code for each inference and tries to execute it.
- if the generated code has syntax errors, specify max_iters = n, to regenerate the code n times
- even if it fails n time, fir error dega, not recommended for prod
- the code generation in the background can result in high latency

ReAct:
- good for running the signature with tools such as web search, weather
- need to specify the tool argument, can be left blank but compulsorily executes in background, that's why latency can be high
